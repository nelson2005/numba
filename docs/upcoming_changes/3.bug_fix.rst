Keep a function's return type when it is passed as a first-class function
-------------------------------------------------------------------------

A jit-compiled function passed as a first-class function
(``numba.types.FunctionType``) argument is no longer compiled with the declared
return type. Previously, the declared return type applied to every later call
of the function with the same argument types. The function is now compiled for
the argument types alone. If its return type differs from the declared one, the
result is converted to the declared type with the conversion a ``return``
statement performs. The conversion can lose information: an ``int64`` result is
truncated when the declared return type is ``int32``. The conversion replaces
the error added in 0.68.0 for a declared return type that does not use the same
LLVM value type as the function's own return type. Numba raises an error if no
conversion exists. This now includes a declared return type that only shares an
LLVM value type with the function's own return type, such as ``datetime64[ms]``
for a function that returns ``datetime64[s]``. Earlier versions accepted such a
function once it was compiled, and read its result as the declared type. If the
receiving function has two explicit signatures that differ only in the declared
return type of that argument, both can match. As before 0.68.0, a call from
Python can then raise ``Ambiguous overloading``, and compiled code takes the
signature declared first.
